## Concrete migration proposal, pending Nick's choice

1. Keep verified legacy root startup redirects throughout 0.6.x. Removing those
   redirects later requires a separately reviewed compatibility change; 0.6.1
   makes no promise that an old root path has already disappeared.
2. Stop generating CLAUDE.md on fresh default/--agent init and never recreate a
   missing legacy CLAUDE.md during upgrade. BOTH native skill destinations stay.
3. For existing exact released/generated CLAUDE.md only, preview retirement to
   retained original bytes under `.mdkg/state/upgrade-originals/<sha256>/CLAUDE.md`.
   The preview names source, retained copy, old/new hashes, affected links, and
   transaction operations. The retained copy survives later journal replacement;
   no automatic expiry or cleanup is added. It is local recovery storage, not a
   guarantee against checkout deletion or host loss.
4. Whole-file retirement needs trusted released seed proof, valid installed
   provenance, no user text outside markers, canonical destination verification,
   and bounded reference inventory. The editable installed manifest alone is
   not trusted release proof. Missing/edited/unknown provenance, outside text,
   unknown hashes, malformed/duplicate markers, edited managed blocks, unknown
   reference files, and unsafe paths preserve/refuse rather than delete.
5. If a user-authored reference still requires the old path, preserve it and
   report the scoped manual merge. No automatic editing of arbitrary user files.
   References cannot become dangling through a selected --only subset. A stale
   preview refuses before effects; retained-original conflicts preserve bytes.
6. Continue using the existing preview/apply/journal/resume/recover machinery,
   with exact fault-injection and recovery controls. No new blanket --force
   interpretation or silent overwrite of user instructions is permitted.

Alternative for Nick: preserve all existing legacy root instructions in 0.6.1,
stop only fresh generation, and defer any removal to a separately reviewed
migration. This is less cleanup and avoids choosing a removal window now.

## Mirror boundaries and observed gaps

Existing config rejects traversal, absolute paths, and normalized duplicates.
Native Git destinations refuse. Synthetic non-force canonical overlap refused
due to an unmanaged-slug collision; that is not proof of structural overlap
admission under --force. Nested targets and case-alias targets were admitted on
this Linux host; they remain unresolved Goal88 acceptance gaps. A custom-only
target list is also admitted and does not silently restore missing defaults.

The implementation should admit all normalized destinations before any effects:
reject canonical/target ancestor overlaps, nested targets, portable case aliases,
symlinks, Git metadata, and duplicate destinations. Extra targets require no
extra root wrappers. Preserve existing custom policy; report exactly which
required native defaults are missing and offer an explicit reviewed config edit.
Do not silently add targets to a user's existing list or reinterpret the current
public CLI as exposing separate skill audit/prune commands.
