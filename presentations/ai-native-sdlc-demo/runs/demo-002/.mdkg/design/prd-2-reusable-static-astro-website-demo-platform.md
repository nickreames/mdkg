# Problem

Coding agents are increasingly capable, but important project context still
disappears between chats, tools, and handoffs. Developers need requirements,
decisions, completed work, rationale, and next steps to remain inspectable with
the code.

Demo 2 must turn that problem into a clear mdkg marketing page while proving
that the reusable source specification and specialized executed specification
retain lineage and differ meaningfully.

# Goals

- Present the promise “Keep the plan when the agent changes.”
- Serve AI-native builders, independent developers, and technical leads without
  reducing the story to enterprise governance.
- Preserve static Astro, semantic HTML, CSS, and zero client JavaScript.
- Use a bright Ocean Flow navigation-chart metaphor with creative latitude over
  exact composition and microcopy.
- Make Plan -> Work -> Evidence and what completed, why, and what comes next
  explicit.
- Integrate the accepted local candidate through the generalized canonical
  adapter and stop at a separate publication gate.

# Non-goals

- Teaching graph forking, subgraphs, or loops on the marketing page.
- Claiming that prompts are obsolete or that mdkg performs coding work.
- Staging, committing, pushing, inspecting deployments, or claiming public
  availability during Goal 4.
- Retaining raw prompts, credentials, tokens, cookies, provider payloads,
  unrelated private context, or bulky runtime traces.

# Requirements

## Functional

- `goal-1` scopes
  `spike-1 -> task-1 -> test-1 -> task-2 -> test-2 -> task-3 -> test-3`.
- `spike-1` records the accepted durable-continuity strategy and page system.
- `task-1` produces a complete local Astro site under `site/`.
- `test-1` records local build, accessibility, claims, safety,
  zero-JavaScript, responsive, and budget evidence.
- `task-2` and `test-2` integrate and validate `/demo/2/` and
  `/demo/2/output/` through the generalized adapter.
- `task-3` and `test-3` remain untouched until Goal 5 separately authorizes
  publication and exact-SHA live verification.
- A fresh-agent pack contains this PRD, the EDD, both decisions, `chk-2`, the
  complete work chain, and required skills.

## Non-functional

- Static semantic HTML and CSS only; no `client:*` directives, hydration
  metadata, generated client JavaScript, runtime scripts, remote fonts,
  analytics, forms, trackers, or third-party runtime assets.
- Ocean Flow palette, keyboard accessibility, visible focus, reduced-motion
  support, and WCAG AA contrast.
- Maximum 500 KiB initial page transfer and 250 KiB per raster asset.
- `listed: false`, `noindex: true`, public alpha and pre-v1 positioning,
  quickstart CTA, and GitHub Issues feedback CTA.

# Acceptance Criteria

- Graph validation passes with zero warnings and routes first to `spike-1`.
- Context-complete packs contain the complete specialized design and work chain.
- Source and specialized `goal-1` snapshots retain the same ID and visibly
  contrast condition, requirements, authority, work, and tests.
- Both local canonical routes render without client JavaScript or public-safety
  violations.
- The child remains unachieved and paused with `task-3` next at Goal 4
  closeout.

# Metrics / Success

- Fresh-agent startup succeeds from `goal-1` without hidden chat context.
- Required packs and operator mirrors remain deterministic.
- Local validation records zero missing routes, unexpected client JavaScript,
  unsafe fields, unsupported claims, or unmeasured acceptance cases.

# Risks

- The continuity promise becomes abstract instead of grounded in source and
  executed goal evidence.
- Marketing copy overstates mdkg capabilities or maturity.
- A local checkpoint is mistaken for publication authority.
- Evidence leaks raw execution context instead of compact public-safe receipts.

# Open Questions

- None for Goal 4. Publication remains a later Goal 5 approval.
