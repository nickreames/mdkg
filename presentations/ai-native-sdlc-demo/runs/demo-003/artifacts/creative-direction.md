# Creative Direction — The Current Map

## Audience and offer

Primary audience: software engineers and technical leaders already using coding
agents who need execution to remain aligned with architectural intent.

Promise: **Give every coding agent the map, the route, and the proof.**
mdkg turns durable Markdown specifications into inspectable work context so a
team can see what completed, why it was done, and what comes next.

## Page structure

1. Hero with the promise, quickstart CTA, and a static “current map” proof card.
2. Context problem: a larger context window is not durable project memory.
3. Plan → Work → Evidence as three connected navigation coordinates.
4. Source-to-execution proof contrasting the reusable starting goal with this
   specialized run.
5. What completed / why / next as a compact outcome ledger.
6. Public-safe graph artifacts and guardrails.
7. Quickstart and feedback CTA.

## Visual territory

Use a bright Ocean Flow “navigation chart” rather than a conventional product
dashboard. Thin route lines, coordinate labels, contour rings, and offset cards
suggest a living map. White and mist surfaces dominate; deep ink text and blue
accents preserve high contrast.

CSS-only motion is limited to a slow route-dash drift and gentle marker pulse,
both disabled under `prefers-reduced-motion`. No imagery is required.

## Static proof

- A route card connects `goal → task → test → checkpoint`.
- Reusable and executed goal excerpts appear side by side.
- An evidence ledger names local validation, canonical integration, exact-SHA
  publication, and public verification as distinct gates.

## Source-backed facts

- mdkg stores project context in a Markdown knowledge graph.
- Its working loop is Plan → Work → Evidence.
- Goals, requirements, decisions, tasks, tests, and checkpoints provide
  inspectable context.
- The CLI can build bounded context packs and route the next scoped work item.
- Publication and provider authority remain explicit external boundaries.

## Non-goals and risks

Do not claim that mdkg replaces Git, guarantees autonomous success, removes
human judgment, or proves general long-horizon autonomy. Do not teach graph
forking mechanics. Test contrast, mobile order, reduced motion, source-backed
copy, zero client JavaScript, and public-safety boundaries.

## Recommendation

Proceed with this direction. It is differentiated, implementable without
assets or runtime JavaScript, and makes Plan → Work → Evidence visible within
the live-demo time budget.
