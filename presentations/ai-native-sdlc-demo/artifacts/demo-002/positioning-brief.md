# Demo 2 positioning brief

## Decision

Position mdkg as the durable continuity layer for AI-native software
development:

> Keep the plan when the agent changes.

The landing page is for developers and technical leads who already use coding
agents but lose decisions, requirements, and next steps when a chat ends or a
different agent takes over. The promise is intentionally narrower than an
enterprise control-plane claim: mdkg keeps a project-readable specification and
evidence trail in Git so humans can remain focused on architecture and planning.

The selected visual metaphor is a bright Ocean Flow navigation chart. A
continuous route moves through Plan, Work, and Evidence while small durable
records remain visible behind each stage. The composition should feel like a
calm product page, not a terminal simulator or an infrastructure dashboard.

## Fixed product and CTA

- Product: mdkg, public alpha and pre-v1.
- Primary CTA: try the mdkg quickstart.
- Secondary CTA: send feedback through GitHub Issues.
- Required story: Plan -> Work -> Evidence; what completed, why, and what is
  next.
- Proof: reusable `goal-1` versus specialized Demo 2 `goal-1`, with linked work
  and local evidence.
- Authority: local candidate only; no publication or provider claim.

## Chosen page direction

- Hero: “Keep the plan when the agent changes.”
- Supporting promise: “Give coding agents durable requirements, decisions, and
  evidence—stored with the work.”
- Audience: AI-native builders, independent developers, and technical leads.
- Narrative sequence:
  1. Agent context disappears; project context should not.
  2. Plan -> Work -> Evidence creates a durable development loop.
  3. A reusable specification becomes a specialized execution goal.
  4. The local result shows what completed, why it mattered, and what comes
     next.
  5. Try the alpha on one real project and report friction.
- Visual language: light-mode Ocean Flow; navigation lines, coordinates,
  evidence stamps, restrained gradients, high-contrast ink, and CSS-only
  ambient motion that disables under reduced motion.
- Imagery: native HTML and CSS only. No remote fonts, third-party scripts, or
  decorative raster dependency.

## Options considered

### A. Durable continuity — selected

Lead with the pain of losing context between agents and sessions. This makes
the value legible to personal-project builders and teams without requiring a
vendor comparison or an enterprise governance frame.

Consequence: copy must stay concrete and prove continuity through the
source-versus-specialized goal contrast.

### B. Agentic SDLC control plane

Lead with coordination, governance, and organizational consistency across many
agents.

Consequence: this is credible as a future direction but too enterprise-heavy
for this rehearsal and more likely to imply capabilities not demonstrated by
the bounded local run.

### C. Prompt replacement

Lead with reusable specifications as an upgrade from copied prompts.

Consequence: the contrast is memorable but unnecessarily adversarial. Prompts
remain useful; the stronger claim is that durable project context complements
them.

## Creative latitude

The implementation agent may choose exact section order, grid, type scale,
navigation-chart geometry, microcopy, and CSS-only motion within the fixed
story and guardrails. It must not add unsupported performance claims,
testimonials, benchmark claims, customer logos, analytics, forms, remote
assets, or publication language.

## Local execution boundary

The accepted allowlist and hashes are recorded in
`goal-4-activation.json`. Goal 4 may create the run, specialize and execute its
local chain, integrate the two local canonical routes, validate them, and seal
the fallback. Demo 2 publication requires a distinct Goal 5 approval.

## Decision evidence

- The user delegated the landing-page visual and marketing direction while
  fixing the product, route, stack, palette, requirements, and safety
  constraints.
- Goal 2 accepted static Astro, zero client JavaScript, per-demo records, and a
  compile-time output-component registry.
- Goal 3 accepted the broader narrative: capable agents still need durable
  specifications, guardrails, and evidence.
- The source graph hash and all interface hashes are pinned in the activation
  receipt.
